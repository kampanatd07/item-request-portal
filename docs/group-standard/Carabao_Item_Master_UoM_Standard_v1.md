## 3. Base UoM กับ Purchase UoM ต่างกันอย่างไร

| ฟิลด์ | ความหมาย | ตัวอย่าง |
|---|---|---|
| **Base UoM** | หน่วยที่ใช้**นับสต็อกและคิดต้นทุน** | `EA` |
| **Purchase UoM** | หน่วยที่**สั่งซื้อจริงจากผู้ขาย** | `BOX` |
| **Pack Size** | 1 Purchase UoM = กี่ Base UoM | `12` |
| **Pack UoM** | หน่วยของ Pack Size | `EA` |

> ตัวอย่าง: ถุงมือยาง ซื้อเป็นกล่อง กล่องละ 12 คู่
> Base = `PAIR` · Purchase = `BOX` · Pack Size = `12` · Pack UoM = `PAIR`

**กฎ:** ถ้า Purchase UoM ≠ Base UoM **ต้องระบุ Pack Size เสมอ** ห้ามเว้นว่าง

## 4. Abbreviation Dictionary

ระบบสกัด UoM จากชื่อสินค้าโดยอัตโนมัติ (`UOM_MAP` ใน `_pipeline/gw_build.py`)
รายการเต็ม 52 คำอยู่ในชีต `Abbreviation` ของไฟล์ xlsx ตัวอย่าง:

| คำที่พบในชื่อ | แปลงเป็น |
|---|---|
| `ml` `มล` `cc` | `ML` |
| `l` `lt` `ltr` `litre` `ลิตร` | `L` |
| `kg` `กก` | `KG` |
| `pcs` `pc` `ชิ้น` `อัน` `ตัว` `ใบ` `ea` | `EA` |
| `box` `กล่อง` | `BOX` |
| `roll` `ม้วน` | `ROLL` |
| `แผ่น` `sheet` | `SHT` |
| `ถัง` `drum` | `DRUM` |

**หลักการเขียนชื่อให้ระบบอ่านออก:** ใส่ **ตัวเลขติดกับหน่วย** เช่น `20L` `500ml` `12ชิ้น`
ถ้าเขียน `ยี่สิบลิตร` ระบบจะอ่านไม่ออกและตกไปเป็นค่าเดา

## 5. วิธียืนยัน 11,898 รหัส — ตัดสินแค่ 118 ครั้ง

ไม่ต้องไล่ทีละรหัสครับ ไฟล์ `Carabao_Item_Master_UoM_Confirm_v1.xlsx` ยุบเป็น **118 การตัดสิน** ตามคู่ (Item Group + Sub-Category + UoM ที่เดาไว้)

**วิธีกรอก** — คอลัมน์ `► UoM ที่ถูกต้อง`:

- ถ้า UoM ที่เดาไว้ถูกแล้ว → ใส่ **`OK`**
- ถ้าผิด → ใส่ **UoM code** จากรายการ 24 หน่วย
- ถ้ากลุ่มนั้นใช้หน่วยเดียวไม่ได้ → ใส่ **`MIXED`** แล้วอธิบายเงื่อนไขในคอลัมน์สุดท้าย

## 6. กฎที่ต้องบังคับหลัง go-live

1. เปิด item ใหม่ **ต้องระบุ Base UoM จาก 24 หน่วยนี้เท่านั้น**
2. ถ้า Purchase UoM ≠ Base UoM ต้องมี Pack Size
3. **ห้ามแก้ Base UoM ของ item ที่มี PO ค้าง** — ต้องเคลียร์ PO ก่อน
4. เพิ่มหน่วยใหม่เข้า master ต้องผ่าน Data Owner
5. KPI `% UoM ที่ยืนยันแล้ว` ต้องถึง **100%** ก่อนเริ่ม cutover เฟส 1
