## 1. ขนาดของงานที่ต้องตัด

| | จำนวน |
|---|---|
| รหัสกลางที่จะออกใช้ | **13,391** |
| บรรทัดที่ต้องแมป (รหัสเดิม → รหัสใหม่) | 13,658 |
| — ฝั่ง CBD | 7,748 |
| — ฝั่ง ACM/APM/APG | 5,910 |
| **1 รหัสใหม่ = หลายรหัสเดิม** (ถูกรวม) | 267 · ข้ามโรงงาน 174 |
| **1 รหัสเดิม = 2 รหัสใหม่** (แตกรหัส) | 271 |
| รหัสเดิมที่จะไม่ยกมา | 249 ตัดออก + 5,316 บล็อกสำรอง |

**สองบรรทัดที่อันตรายที่สุดคือ 267 กับ 271** — ความสัมพันธ์ไม่ใช่ 1:1
ระบบอัตโนมัติที่ map แบบ 1:1 จะพังตรงนี้ ต้องจัดการด้วยมือหรือมีกฎเฉพาะ

## 2. อะไรบ้างที่อ้างรหัสสินค้า (ต้องสำรวจให้ครบก่อน)

ทำ inventory นี้ให้เสร็จก่อนกำหนดวัน cutover — **ห้ามเดา**

| ที่อยู่ของรหัส | เจ้าของ | ผลถ้าลืม |
|---|---|---|
| PO ที่เปิดค้าง / ยังรับของไม่ครบ | จัดซื้อ | รับของไม่ได้ ปิด PO ไม่ได้ |
| PR ที่ยังไม่แปลงเป็น PO | จัดซื้อ | ต้องเปิดใหม่ทั้งใบ |
| สัญญา / Blanket order / ราคาตกลง | จัดซื้อ | ราคาหลุด กลับไปซื้อราคาตลาด |
| BOM / สูตรการผลิต | Production / R&D | สั่งผลิตไม่ได้ |
| Min-Max / Reorder point | คลัง | ของขาดหรือของล้น |
| Vendor catalog / Punch-out | จัดซื้อ + IT | สั่งซื้อออนไลน์ไม่ได้ |
| ประวัติ spend / รายงาน BI | Procurement Strategy | เทียบ YoY ไม่ได้ |
| รายงานที่ hardcode รหัส (Excel/Power BI) | ทุกแผนก | เงียบๆ แล้วผิด — **อันตรายที่สุด** |
| Interface กับระบบภายนอก (EDI, e-Tax) | IT | ส่งข้อมูลไม่ผ่าน |
| Asset register (16 รายการเครื่องจักร) | Accounting | ผูก FA ไม่ได้ |

> ช่องสุดท้ายที่ต้องเติมคือ "ใครเป็นเจ้าของ" — ถ้าเว้นว่างไว้ แปลว่ายังไม่มีใครรับผิดชอบตอนของพัง

## 3. กลยุทธ์ที่แนะนำ — Dual-code แบบมีวันหมดอายุ

พิจารณา 3 ทาง:

| ทาง | ข้อดี | ข้อเสีย | ประเมิน |
|---|---|---|---|
| **Big-bang** ตัดทีเดียวทั้งกลุ่ม | จบเร็ว ไม่มีสองมาตรฐาน | ถ้าพลาด = ทั้งกลุ่มหยุด · ต้องหยุดระบบยาว | ❌ เสี่ยงเกินไปที่ 13,391 รหัส |
| **Dual-code ถาวร** เก็บรหัสเดิมเป็น alias ตลอดไป | ไม่กระทบใครเลย | ไม่มีวันได้ master เดียวจริง · ปัญหาเดิมกลับมา | ❌ ไม่บรรลุเป้าหมาย |
| **Dual-code มีวันหมดอายุ** ✅ | เสี่ยงต่ำ · ย้อนกลับได้ · บังคับให้จบ | ต้องคุมวินัยช่วงคู่ขนาน | ✅ **แนะนำ** |

**สาระสำคัญ:** ใส่รหัสเดิมลงในฟิลด์ค้นหาของ item ใหม่ (`Search name` / External item number) แล้ว**ประกาศวันปิดการค้นด้วยรหัสเดิมล่วงหน้า** — ไม่ใช่ปล่อยให้ค่อยๆ เลิกใช้เอง

ไฟล์ `New_Item_Master` มีคอลัมน์ `Legacy Code (CBD)` และ `Legacy Code (ACM/APM/APG)` ให้อยู่แล้ว ใช้โหลดเข้าฟิลด์นี้ได้ตรงๆ

## 4. ลำดับเฟส

### เฟส 0 — เตรียม (ก่อน cutover 6-8 สัปดาห์)

- [ ] สำรวจ inventory ตามข้อ 2 ให้ครบ พร้อมชื่อเจ้าของทุกช่อง
- [ ] **ตั้งเจ้าของทะเบียนเลขรันกลาง** (ดู Governance doc) — ถ้ายังไม่มี ห้ามเริ่มเฟส 1
- [ ] ยืนยัน UoM 11,898 รหัสที่ยังเป็นค่าเดา (ดู UoM doc)
- [ ] Accounting ยืนยัน 16 รายการเครื่องจักรว่าเป็น Fixed Asset หรือไม่
- [ ] freeze การเปิด item ใหม่ในรหัสเดิม — ตั้งแต่วันนี้เปิดใหม่ต้องใช้รหัสกลาง

### เฟส 1 — โหลด master ใหม่ (ยังไม่เลิกใช้ของเดิม)

- [ ] โหลด 13,391 รหัสเข้า D365 ในสถานะ **Active แต่ยังไม่ประกาศ**
- [ ] ใส่รหัสเดิมลงฟิลด์ค้นหาทุกตัว
- [ ] 63 รหัสที่ `Lifecycle = Blocked` โหลดด้วยแต่ห้ามเปิด PO
- [ ] ตรวจ: ค้นด้วยรหัสเดิมแล้วต้องเจอ item ใหม่ทุกตัว — **สุ่ม 200 ตัว ต้องผ่าน 100%**

### เฟส 2 — คู่ขนาน (แนะนำ 8-12 สัปดาห์)

- [ ] เปิด PR/PO ใหม่ **ใช้รหัสกลางเท่านั้น**
- [ ] PO เก่าที่ค้างอยู่ **ปล่อยให้จบด้วยรหัสเดิม** ไม่ต้องแก้ย้อนหลัง
- [ ] แมป BOM / สัญญา / Min-Max ทีละชุดตามลำดับความเสี่ยง
- [ ] จัดการ **267 รายการที่ถูกรวม** และ **271 ที่แตกรหัส** ด้วยมือ พร้อมผู้ยืนยันรายตัว
- [ ] รายงาน BI ทำ mapping layer ให้เทียบข้ามช่วงได้ (อย่าแก้ข้อมูลย้อนหลัง)
- [ ] ติดตามรายสัปดาห์: % ของ PR ใหม่ที่ใช้รหัสกลาง — เป้าหมาย 100% ภายในสัปดาห์ที่ 6

### เฟส 3 — ปิดรหัสเดิม

- [ ] เงื่อนไขที่ต้องครบก่อนปิด (ทุกข้อ):
  - PO ค้างด้วยรหัสเดิม = 0
  - BOM ที่ยังอ้างรหัสเดิม = 0
  - สัญญาที่ยังอ้างรหัสเดิม = 0
  - PR ใหม่ที่ใช้รหัสเดิม = 0 ติดต่อกัน 4 สัปดาห์
- [ ] เปลี่ยนรหัสเดิมเป็น Blocked (**ห้ามลบ** — ประวัติ spend ต้องอ่านได้ตลอดไป)
- [ ] ปิดการค้นหาด้วยรหัสเดิม
- [ ] ประกาศปิดโครงการ

## 5. Rollback — เงื่อนไขและวิธี

**ตัดสินใจ rollback ถ้าเจอข้อใดข้อหนึ่งภายใน 2 สัปดาห์แรกของเฟส 2:**

- เปิด PO ไม่ได้เกิน 5% ของปริมาณปกติ
- พบรหัสชนกันในระบบจริง (ไม่ควรเกิด แต่ต้องมีทางถอย)
- BOM สั่งผลิตไม่ได้แม้แต่รายการเดียว

**วิธีถอย:** เพราะรหัสเดิมยัง Active อยู่ตลอดเฟส 2 การถอยคือ *"หยุดใช้รหัสใหม่ กลับไปใช้รหัสเดิม"* — ไม่ต้อง restore ข้อมูล
นี่คือเหตุผลหลักที่เลือก dual-code ไม่ใช่ big-bang

## 7. สิ่งที่เอกสารนี้ยังตอบไม่ได้ (ต้องเติมจากหน้างาน)

1. **จำนวน PO ที่ค้างอยู่จริง** — ต้องดึงจาก D365
2. **จำนวน BOM ที่อ้างรหัสในขอบเขตนี้** — ต้องถาม Production
3. **ปฏิทินธุรกิจ** — ห้ามตัดช่วงปิดงบ / ช่วง peak การผลิต
4. **ใครเป็นเจ้าของแต่ละช่องในข้อ 2** — ยังว่างทั้งตาราง
5. **งบและกำลังคน** — เฟส 2 ต้องมีคนดูแลเต็มเวลาอย่างน้อย 1 คน

> 4 ข้อแรกใช้เวลารวบรวมไม่เกิน 1 สัปดาห์ และเป็นตัวกำหนดวัน cutover จริง
